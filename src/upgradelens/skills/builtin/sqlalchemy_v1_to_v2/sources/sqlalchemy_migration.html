SQLAlchemy 2.0 released

SQLAlchemy 1.x → 2.0 Migration Guide

This is an offline snapshot of the SQLAlchemy 1.x to 2.0 migration guide, used by the UpgradeLens tests. It is a trimmed copy of the public migration guide covering the most common breaking changes when moving from SQLAlchemy 1.x to 2.0.

Import relocations

Several imports moved in 2.0; the old sqlalchemy.ext entry points were removed.

declarative_base → sqlalchemy.orm

The sqlalchemy.ext.declarative package was removed in 2.0. Import declarative_base and declared_attr from sqlalchemy.orm instead.

from sqlalchemy.orm import declarative_base

Base = declarative_base()

hybrid_property → sqlalchemy.orm

The sqlalchemy.ext.hybrid package was removed in 2.0. Import hybrid_property and hybrid_method from sqlalchemy.orm instead.

from sqlalchemy.orm import hybrid_property, hybrid_method

Query API

The 1.x Query interface is deprecated in 2.0 style. Prefer select() executed through a Session.

session.query() → select()

session.query(Model) is deprecated. Use session.execute(select(Model)).scalars(). The return type changes from Query to Result, so call .scalars() or .scalar_one() to obtain objects.

stmt = select(User).where(User.id == 1)
user = session.execute(stmt).scalar_one()

Query.get() → Session.get()

Query.get() was removed in 2.0. Use Session.get(Model, id) to load by primary key. Unlike the old Query.get(), the 2.0 method is a direct Session method.

user = session.get(User, 1)

Engine execution

Executing statements directly on an Engine is no longer supported in 2.0.

engine.execute() → connection.execute()

Engine.execute() is removed. Obtain a Connection via engine.connect() and call connection.execute(). When passing parameters, use a statement object such as text() and pass parameters as a dictionary rather than positionally.

with engine.connect() as conn:
    conn.execute(text("SELECT * FROM users WHERE id = :id"), {"id": 1})
